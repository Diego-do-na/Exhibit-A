# Related work and positioning

## Positioning statement

Security tools frequently present maintainers with backlogs of unverified warnings that demand manual triage. Static analyzers, dependency scanners, and LLM code assistants identify suspicious patterns or advisory matches, but they do not verify whether a weakness can be triggered under realistic execution. Conversely, automated exploit generators and penetration tools focus on offensive demonstration without verified remediation. Exhibit A occupies a narrow, complementary position: it reports only what it can prove with an exploit test that fails on the vulnerable code for an intended, oracle-observed reason in an isolated, resource-limited sandbox, and then passes once a verified fix is applied while baseline tests continue to pass and defender bypass variants are evaluated. A green result means "nothing could be proven", never "safe".

## What Exhibit A does not do

1. **Does not replace static analysis**: Static analyzers (such as Semgrep, CodeQL, and Bandit) run quickly without executing code and cover broad pattern sets, style checks, and unexercised code paths. Exhibit A is a narrow verification engine that addresses only provable runtime effects.
2. **Does not claim safety**: A green run or absent finding means "nothing could be proven", never "safe". Test execution occurs inside an isolated and resource-limited sandbox, never "100% safe".
3. **Does not eliminate residual oracle limits**: Dynamic verification is bounded by documented residual limits R1–R6 (detailed in [docs/oracle/oracle-provenance.md](oracle/oracle-provenance.md) section 7):
   - **R1**: in-process introspection of the hook and key on the host execution path;
   - **R2**: `sitecustomize.py` execution prior to plugin setup on the host path;
   - **R3**: subprocess canary reads unobserved by the in-process Python hook;
   - **R4**: ctypes or native library canary reads unobserved by CPython audit hooks;
   - **R5**: dependency monkeypatching via computed names to induce genuine application calls;
   - **R6**: obfuscated test-chosen application roots bypassing static guard checks.
4. **Does not apply automated remediation without human review**: Fixes and exploit tests are generated as reviewable candidate pull requests accompanied by evidence bundles; nothing merges itself.
5. **Does not scan entire third-party package repositories or secret configurations**: Scanning whole registries or secret tokens is an explicit non-goal (SPEC section 2). Dependency queries serve only as entry-point reachability hints for verification.
